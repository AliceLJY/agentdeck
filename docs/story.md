# AgentDeck：手机浏览器里的真终端，给命令行 AI 工具一人一个标签

> 状态：v0.3.0（2026 年 8 月 13 日），自部署，服务端跑在自己的 Mac 上，手机、平板、电脑用浏览器连。开源，MIT 协议。还在维护，也还在用：它常驻在我的 Mac mini 上。
> 入口：[GitHub 仓库](https://github.com/AliceLJY/agentdeck) · [发布说明](https://github.com/AliceLJY/agentdeck/releases)（没有安装包，克隆下来自己跑）

## 它解决什么

人在外面，想接着用家里 Mac 上的 Claude Code。我最早的办法是 Tailscale 加 mosh，终端是真的，但 mosh 一次只能开一个会话，想同时改两个项目就得开两个连接。后来的 Telegram 机器人是遥控器，只适合短指令；再后来的网页聊天客户端把 CC 的输出翻译成聊天气泡，diff 在气泡里挤成一坨，没有颜色没有对齐。盯了五分钟我才反应过来：我在用聊天框看代码变更。

AgentDeck 要的是 mosh 那种真终端体验，但在一个浏览器页面里开多个会话，手机、iPad、电脑通吃。现在它给 Claude Code、Codex、Kimi Code、Antigravity 四个命令行工具各一个标签页；会话跑在 tmux 里，服务重启、浏览器关掉都不丢；真终端之上可以切一层对话视图，它读的是 CLI 自己写在磁盘上的记录，长回复完整可滚，要点 TUI 里的选择框时一键切回真终端。

## 起点

2026 年 4 月 14 日第一次提交，那时它叫 cc-remote-term，只服务 Claude Code。灵感是刷推时看到有人用 xterm.js 加 node-pty 加 WebSocket 在浏览器里跑了个终端模拟器；我想了三秒：加个侧边栏管多会话，加 tmux 做持久化，不就是浏览器版的多窗口 mosh。头两天全在和乱码打交道：iOS 上 WebGL 把字符渲成马赛克，iPadOS 的 Safari 自称 Macintosh，tmux 的 DA 响应绕回 xterm.js 面前成了天书。

5 月加了 Codex 和跨后端的历史浏览，7 月初有了对话视图。7 月 28 日改名 AgentDeck，因为它已经不只是 CC 的了：当天接进 Kimi，两天后接进 Antigravity。8 月 13 日发 v0.3.0。到 9 月 6 日一共 118 次提交、3 个版本 tag，其中 7 月一个月就有 70 次。

## 几个关键取舍

- **真终端，不做阉割版聊天框。** xterm.js 渲染完整的终端转义序列，TUI、颜色、权限提示全部原样。对话视图是叠在上面的可选层，只读 transcript 文件，终端那条路一行不动。
- **tmux 留下。** 乱码最严重时 Claude Code 真的回滚过一版，去掉 tmux 改成纯 PTY 直连，被我一句话拍回去：那重启不是又没办法接着用了？功能砍掉不叫解决问题。
- **门锁两道，第二道是设备而不是密码。** token 只把你带到门口，浏览器还得是已批准的设备；陌生设备拦住并推一条带一次性批准链接的 Telegram 通知，链接一分钟过期。手机丢了撤销那一台，其他设备照常。
- **限流只对失败计数，用延迟不用拒绝。** 我的流量经隧道进来，服务端看到的每个远程客户端都是本机地址，按 IP 限流会把我和攻击者算成同一个人，共享配额会变成把我锁在门外的杠杆。所以 60 秒内 5 次失败免费，之后每次加 250 毫秒，封顶 3 秒；正确 token 加已批准设备永远不碰计数器。
- **传输层不认 CLI，理解层按 CLI 适配。** PTY、tmux、标签栏、上传、触摸滚动跟对面是什么程序无关；对话视图、历史、一键 resume 要读各家的 transcript，接一个新后端是一天的适配活，分发已改成穷举，漏接一条线会在编译期报错。

## 怎么做出来的

这个项目通过 AI 协作完成。Claude Code 承担了绝大部分设计与实现，118 次提交里 97 次带它的署名；Codex 参与了 v0.3.0 的发版前审计与准备；我定需求，拿 iPhone、iPad、安卓手机做真机测试，在分歧处拍板，比如本地目录名不跟着改：它是我在外面唯一的通路，不为好看动它。v0.3.0 发版时有 144 个自动化测试把关。

## 踩过的坑

- **五次「修好了」，四个洞是它自己留的。** 加设备白名单那天，自动审查先报了个 HIGH：判断「是否本机」的 IP 读的是调用方自己填的请求头。修完、红绿对照做了、三台设备走通了，日志第一行却是 Adopted：我的 iPhone 没走批准就被收养。我的链路走 frp 隧道，每个远程客户端到达服务端时 peer 都是 127.0.0.1，「从本机来就信任第一台」在真实部署下恒为真，测试模拟的远程恰好绕开了这条路。修法是把整条自动信任删掉，不是再加判据。收尾时我随口一句「没刷新的页面看不到提醒」，又顺出两个：Service Worker 是 cache-first，每台设备被钉在第一次加载的版本上；撤销只改了一行 JSON，已连着的会话不会被掐断。现在前者改成 network-first，后者经心跳一轮内掐断，实测 26 秒。
- **服务在跑旧代码，没有任何报错。** 启动脚本直接起服务、从不重新构建，自动拉取把代码更新到位了，`.next` 还是旧的。两次撞上之后改成启动前先构建，构建失败就大声告警、用旧构建继续起，因为丢掉远程入口比跑一份旧代码更糟。
- **Agy 标签起的是 Claude，八天没人发现。** 找可执行文件的函数只给 kimi 和 codex 写了分支，其余全落到 claude；兜底的 which claude 永远成功，从来没有一句 not found 可看，前端还有五处同一个病。修法是穷举加测试断言每个后端查的是自己的 CLI；教训是代码层和部署层全绿两次都没能说明 Agy 能用，只有开一次标签算数。
- **终端翻不上去，三份实测互相打架。** 三份都是真数据，只是测的对象不同：一份是自己灌进 xterm 的，一份是 tmux 新会话的 0 行，一份是开了几个小时的老会话攒的。中间还因为拿提交时间当上线时间，把我亲口验证过的修复回滚了一次。修法是承认历史在 tmux 手里：attach 时先用 capture-pane 把 scrollback 捞出来发给浏览器，再回放环形缓冲。

## 现在的边界

- 服务端只在 macOS 上跑过，Linux 要自己重新编译 node-pty。
- 设备标识不是第二把钥匙：token 和某台已批准浏览器的 localStorage 一起被复制走，对方看起来就是那台浏览器；「同一设备同时从两处连」这个信号还没做。
- 历史列表只取最近 25 个会话，搜索不翻页。
- 还在用：常驻在我的 Mac mini 上，2026 年 9 月 8 日核实在跑，从外面通过 Tailscale 私网连进来。本地目录名还叫 cc-remote-term，有意不改。
- 一条小尾巴：两个改版后不再引用的旧组件还留在仓库里，等确认不回退再删。
